## Why
        primer-mcp claims that agents plan before they code when it is available: they state why the work matters, record decisions, break work into tasks, and verify what they finish. There is no evidence for this yet. For an AI engineering portfolio, an evaluation is that evidence, and the result feeds back into primer-mcp's README.

        ## Goals
        - Run an agent on the same coding tasks with and without primer-mcp
- Compare its behaviour: planning before coding, creating tickets, recording completion notes and verification evidence, staying in scope
- Report headline numbers that the primer-mcp README can link to

        ## Constraints
        - Small: about 10-20 tasks with a few runs each; grow only if the results are unclear
- Pin the primer-mcp version (uvx primer-mcp==X.Y.Z) so results say which release was measured
- Prefer automatic checks on files and git history over elaborate judging

        ## Non-Goals
        - A general benchmark framework or multi-provider harness
- Measuring code correctness beyond a basic functional check
- Running the evaluation in CI

        ## Success Criteria
        - ADRs record the test app, harness, baseline, metrics and runs per task
- A reproducible run produces per-task behaviour metrics for both arms
- The headline results are published here and linked from the primer-mcp README
