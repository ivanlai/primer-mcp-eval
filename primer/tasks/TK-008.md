## What to do
Build a single runner script that takes scenarios, arms, repetitions and a batch name (pilot or headline), and gives each run a fresh fixture repo, an isolated home directory and pinned versions. It prepares the primer arm with init_project, runs claude -p with the composed prompt, and saves the transcript, final repo and metadata. It checks isolation from the saved init message. It has a dry-run mode, and can take a stand-in claude binary so the whole pipeline can be tested offline without paid calls.

## Testable Outcome
Offline: a dry run prints the exact command, environment and prompt for each run, and a run with a stub claude produces the full output layout for both arms, with the primer arm initialised and the baseline not, and the isolation check passing for good stubs and failing for a leaky one. The first real run is left for the pilot.

## Completion Notes
run_eval.py runs scenarios as isolated headless sessions with pinned versions; tested offline with a stub claude (9 passed); real runs need ANTHROPIC_API_KEY

- `scripts/run_eval.py --batch pilot|headline [--scenario] [--arm] [--reps] [--dry-run] [--claude]`. Output goes to runs/<batch>/<scenario>/<arm>/r<n>/ (gitignored): prompt.txt, command.json, transcript.jsonl, stderr.txt, meta.json and repo/. Finished runs are skipped, so a batch can be resumed.
- Isolation: each session gets an empty temporary HOME, an allowlisted environment (PATH, locale, API key, uv cache), --strict-mcp-config with a per-arm config, and --no-session-persistence. Git in the run repo ignores global and system config, so the developer's hooks don't apply.
- Fixture: exported from git HEAD, `git init`-ed with a neutral "Initial commit" by "Developer". The primer arm has init_project (at the pinned primer-mcp, via its Python API; there is no CLI init) applied before that commit, so both arms start from a clean tree.
- Pins and limits live in eval.toml: CLI 2.1.283 (checked before any real run), primer-mcp 0.1.7, model, a $2 per-run budget, a 30-minute timeout, and bypassPermissions.
- The isolation check reads the transcript's init event: the baseline must have no MCP servers or tools, and the primer arm must have exactly primer-mcp with its tools.

### Details
Decisions flagged for Ivan (all are values in eval.toml or one line of code): the model is claude-sonnet-5 (the cheaper choice; his call); the $2 cap; and bypassPermissions, which unattended runs need but which means the agent runs commands with his user's privileges, limited only by the temporary HOME and working directory. Auth: the empty HOME has no stored login, so real runs need ANTHROPIC_API_KEY; copying his OAuth credentials into each temporary HOME was deliberately not done. User-level instructions can't be seen in stream-json, so that half of the isolation check is structural (the HOME is empty) rather than read from the transcript. The pilot must confirm the real init event carries `tools` and `mcp_servers` as assumed. The offline tests caught one flaw in the tests themselves: a variable set in the test environment never reached the stub, because the runner allowlists the environment, which is the isolation working.
