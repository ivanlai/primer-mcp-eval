## Parent Story
[[ST-001]]

## What to do
Build the fixture as a small expense tracker command-line app in its own subdirectory: add, list and categorise expenses, store them as JSON, and produce monthly summaries. Give it a pytest suite that passes. Leave room for the ST-002 features and refactors, and include nothing primer-related or any planning documents.

## Testable Outcome
In the fixture directory, pytest passes, the app runs its core commands end to end, the code is about 500-800 lines, and there is no primer/, CLAUDE.md, AGENTS.md or planning document.

## Dependencies
- (none)

## Completion Notes
Expense tracker fixture in fixtures/app: add/list/categories/summary CLI, JSON storage, 53 passing tests

- Standard library only; pytest is a dev dependency pinned by uv.lock. About 610 lines including tests.
- Amounts are whole pence, parsed with Decimal. Categories are case-insensitive. The data file comes from --file, $EXPENSES_FILE or ~/.expenses.json.
- Deliberately missing, to leave room for ST-002 tasks: edit/delete, budgets, CSV import/export, recurring expenses, date ranges.
- No README, primer/, CLAUDE.md, AGENTS.md or planning docs.

### Details
The runner (ST-003) should copy the fixture from git, not from the working tree, so the gitignored .venv and .pytest_cache don't reach runs. Whether to ship a README is left to ST-002: if a feature task naturally updates usage docs, ADR-004's durable-record rule has to tell that apart from planning notes.
