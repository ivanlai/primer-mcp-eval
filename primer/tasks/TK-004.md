## What to do
Write four multi-step feature tasks for things the fixture deliberately lacks (candidates: edit/delete, budgets, CSV import/export, recurring expenses). They should be big enough that planning is a reasonable choice. Each prompt reads like a user request, and each check tests only the behaviour the prompt asks for, not a particular design.

## Testable Outcome
Four feature task directories in the TK-003 format. Each check fails on the fixture and passes with its reference solution, the shipped suite passes with each reference, and each expected file set covers its reference diff.

## Completion Notes
Four feature tasks (edit/delete, budgets, CSV export/import, recurring), each with a check and a reference; 7/7 tasks valid

- feature-edit-delete: `delete ID`, `edit ID` with optional fields; unknown IDs are errors; IDs are never reused.
- feature-budgets: `budget set/list`; summary shows the budget and what's left, or `over budget`; old data files still load (a data-format change).
- feature-csv: `export`/`import` with a fixed header; all-or-nothing import that reports the bad line numbers; export then import round-trips.
- feature-recurring: `recurring add/list/apply`; applying is idempotent per month; day 31 falls on the last day of a short month.
- Prompts fix the CLI interface, since a check can only find a feature that way, and leave the design open. The checks accept any output layout that carries the asked-for facts.
- expected_files now accepts glob patterns (validator and README), because a feature may add modules whose names can't be known in advance. All four use `src/expenses/*.py`.

### Details
The feature checks steer clear of the planted bugs: amounts are ones a float stores exactly (12.50, 3.00, 7.25, 950.00), categories are lower case, and no month is compared across years. That way a feature run can't fail because of bug B, or be pushed into fixing it out of scope. None of the references touch a planted-bug line (grep checked). The consequence is that the scope metric is weak for features, since the whole package is in scope; the bug, refactor and trivial tasks carry most of that signal. After review with Ivan, the checks were cut back to assert only what each prompt states (now a rule in tasks/README.md). That dropped three unstated traps: a comma inside a CSV note, leap-year February, and applying separate months. The budgets check was also loosened to accept budgets shown in a separate section, not only on the category line. The references were written in a scratch git copy of the fixture, one branch per feature, and exported as patches.
