## Completion Notes
Two refactor scenarios (render_summary, serialisation into storage) and two trivial scenarios (average label, category counts); 12/12 scenarios valid

- refactor-render-summary: move the summary text into `reports.render_summary(summary) -> str`. The check tests that the function exists and that the CLI output is byte-identical to the shipped output.
- refactor-serialisation: move `Expense.to_dict`/`from_dict` into storage. The check tests that `Expense` has neither method and that an existing data file still loads and extends.
- trivial-average-label: "Daily average" becomes "Average per day".
- trivial-category-counts: `categories` prints `food (3)`.
- Each check is one light structural or output assertion; the fixture's own suite is the evidence that behaviour is otherwise unchanged. Every reference also updates the shipped test that asserted the old behaviour, so running and fixing tests is part of doing each scenario.
- Renamed `tasks/` to `scenarios/` (with `task.toml` becoming `scenario.toml` and `validate_tasks.py` becoming `validate_scenarios.py`), so that "task" only ever means a primer-mcp ticket. Ivan found the double meaning confusing. Open stories ST-002 to ST-006 were reworded to match; completed tickets keep the old name as the record of what was true when they were done.
