## Completion Notes
Planted three bugs (month ignores year, float amounts, case-sensitive category filter); held-out checks in checks/

- A, month ignores year (`reports.py`): `summary` and `list --month` include the same month from other years. Symptom for the prompt: the 2026-03 summary includes March 2025 expenses.
- B, float amounts (`models.py`): amounts are parsed as float, so 0.29 is stored as 0.28 (also 0.57, 1.15, 4.35, 19.99). Symptom: a 0.29 stamp lists as 0.28.
- C, case-sensitive category filter (`cli.py`): `list --category Groceries` finds nothing. Symptom: the capitalised filter shows nothing, the lower-case one works.
- Shipped suite still passes. Two test inputs were changed to open the gaps: the 2025-03 row was dropped from the reports test data, and "FOOD" became "food" in one CLI test. B needed no test change.
- The checks drive only the CLI's `main()`, so fixes that refactor internals are still judged fairly.

### Details
Rejected D (daily average divides by 30): it would be a second bug in reports.py, the test that would have to go is named after the behaviour, and its prompt would give away the cause. B was planted as a natural float-based parser, not a stray float() call, so its diff doesn't look planted. Runs must start from a fresh `git init` of the fixture (ST-003); copying this repo's history would show the planting commit. ST-002 may move the checks when it settles the task layout.
