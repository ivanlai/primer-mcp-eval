## Parent Epic
        [[EP-001]]

        ## Context
        The eval needs an agent that runs unattended on each task in both arms, with a transcript we can analyse afterwards. primer-mcp works through two things: its MCP tools and server instructions, and the workflow section it adds to the project's CLAUDE.md. If the harness drops either one, the primer arm isn't primer-mcp as people actually use it. The machine running the eval also has user-level config that would leak into runs if nothing isolates them: a global ~/.claude/CLAUDE.md full of planning guidance, and ~/.mcp.json, which includes primer-mcp.

        ## Decision
        Run each task with headless Claude Code (claude -p) at a pinned CLI version. Record every run with --output-format stream-json so the checks can read the tool calls. Give each arm its own --mcp-config and pass --strict-mcp-config: the primer arm gets a pinned uvx primer-mcp==X.Y.Z, and the baseline arm's contents are set by the baseline ADR. Each run gets a fresh temporary copy of the fixture and a clean user config directory, so no user-level CLAUDE.md, MCP servers, memory or hooks can reach it. Don't use --bare, because it turns off CLAUDE.md discovery. Pin the model and set a per-run budget cap.

        ## Alternatives Considered
        - Claude Agent SDK (Python): rejected because it runs the same agent loop and adds only programmatic control, which this eval doesn't need. CLAUDE.md loading has to be switched on explicitly, and if that were missed quietly the primer arm would lose half its mechanism
- A hand-written tool loop on the Messages API: rejected because it means rebuilding file and shell tools, so the eval would measure our harness instead of an agent people actually use
- Headless runs in the developer's normal environment: rejected because the global CLAUDE.md and ~/.mcp.json would reach both arms, making the baseline plan more and giving it primer-mcp

        ## Consequences
        The results describe Claude Code specifically, the agent primer-mcp targets, and not agents in general. That generality is a non-goal. The runner stays a small subprocess wrapper. We depend on the CLI's flags and stream-json format staying the same at the pinned version. The isolation has to be proved, not assumed: the runner should check each baseline transcript for no primer tools and no user-level instructions. Every run costs money through the API, so the budget cap and the runs-per-task decision set the total cost.
