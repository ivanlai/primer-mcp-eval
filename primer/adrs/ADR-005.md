## Parent Epic
        [[EP-001]]

        ## Context
        Agent behaviour varies from one session to the next on the same prompt, so one run per task can't separate primer-mcp's effect from noise. Every run is a paid API session, and the cost per run isn't known until the runner exists: it depends on the pinned model and how many turns each task takes. The runner and the checks (ADR-002, ADR-004) are also untested, so the first full pass is likely to expose pipeline bugs. Runs of the same task aren't independent, so the analysis must not treat every run as a separate sample.

        ## Decision
        A run is one headless session on one task in one arm, starting from a fresh copy of the fixture. First, a pilot: every task once in each arm (24 runs). It validates the runner and checks end to end, measures the real cost per run, and supplies the transcripts for hand-reading (ADR-004). Pilot results are excluded from the headline. Then the main run: every task 3 times in each arm (72 runs), at the same pinned CLI, model and primer-mcp versions. We extend to 5 runs per task only if the confidence intervals overlap and the difference looks plausible, and only after checking the cost against the pilot's per-run figure. Results are reported per arm as rates with confidence intervals bootstrapped over tasks, together with the per-task difference between arms.

        ## Alternatives Considered
        - A fixed 5 runs per arm with no pilot (120 runs): rejected because it spends the largest budget before the runner and checks are proven
- A fixed 3 runs per arm with no pilot: rejected because the first real pass would double as the debugging pass, so bugs found during it would contaminate the headline runs
- One run per task: rejected because it can't tell an effect from session-to-session variance
- Treating all runs as independent samples: rejected because repeated runs of one task are correlated, which would overstate how certain the results are

        ## Consequences
        36 runs per arm are enough to detect large differences (roughly 30% against 70% on a yes/no metric) but not subtle ones, and the report will say so. Total cost is set after the pilot, not guessed now. The pilot needs its own output location so it can't mix with the headline results. Any change to the fixture, prompts or checks after the main run starts means rerunning both arms.
