## Parent Epic
[[EP-002]]

## Context
The headline shows primer-mcp moving planning before the first code edit from 0/15 to 15/15 on features and open-ended requests, but the primer arm had the tools and a CLAUDE.md section, so the effect could come from either. The objection to answer is 'couldn't a line in CLAUDE.md saying plan first do the same?'. The planning metric (ADR-004) counts plan-mode tools, the Plan agent, ticket tools and Markdown writes before the first source edit; a plan written only in chat isn't counted. The Claude Code binary pinned for the headline (2.1.283) is no longer installed.

## Decision
Add a third arm, 'instructions': the baseline configuration (no MCP servers) plus a CLAUDE.md in the repo containing only 'Plan first.', committed in the initial commit as the primer arm's files are. It runs all 12 scenarios 3 times (36 runs) at the headline pins and is scored with ADR-004's rules unchanged, then compared with the existing baseline and primer runs. If 2.1.283 can't be reinstalled or claude-sonnet-5 is no longer served, all three arms are rerun at new pins instead.

## Alternatives Considered
- primer-mcp's CLAUDE.md section rewritten without tool names: rejected for now because it tests detailed instructions against tools, not the one-line objection; it stays a follow-up if the one-liner falls short
- Both instruction variants as two arms: rejected because it doubles the runs before knowing whether the simple version already matters
- Features and the ambiguous request only (15 runs): rejected because it leaves bug fixes and refactors uncompared, and that gap would be easy to challenge
- Counting plans written in chat: rejected because it needs a judge or a heuristic over chat text, which breaks ADR-004's deterministic scoring, and a chat plan leaves no record, which is part of what's claimed

## Consequences
If the one-liner matches primer-mcp on planning, the steering comes from instructions and the tools' value is the structured record; if it doesn't, the tools' replies are doing the steering. An agent that plans only in chat scores zero, so transcripts are spot-read for chat plans and the README reports them, so the result isn't misread. Comparing against the headline runs is only valid at identical pins.
